# Клиентская часть

## Общая характеристика

Клиентская часть проекта `Универ` находится в пакете `webapp`. Приложение построено на Expo, React Native и React Native Web, поэтому один набор экранов используется для мобильной и web-среды.

Клиент не содержит критической бизнес-логики: он отображает состояние, собирает данные форм и вызывает серверные процедуры. Проверки прав и окончательная валидация выполняются на сервере.

Основные задачи клиентской части:

- отображение пользовательского интерфейса;
- навигация между экранами;
- работа с формами;
- выполнение запросов к tRPC API;
- хранение токена авторизации;
- загрузка изображений;
- обработка пользовательских ошибок;
- отправка клиентских ошибок и аналитики.

## Корневой компонент

`App.tsx` подключает основные провайдеры:

- `TrpcProvider` для tRPC и React Query;
- `AppContextProvider` для состояния текущего пользователя;
- `AppFeedbackProvider` для пользовательской обратной связи;
- `MixpanelUser` для аналитики;
- `SentryUser` для связи ошибок с пользователем;
- `NavigationContainer` для навигации.

Для web-версии корневой компонент дополнительно задает оболочку приложения, максимальную ширину и высоту viewport, чтобы интерфейс выглядел как мобильное приложение внутри web-страницы.

## Навигация

Навигация построена на React Navigation. Используются:

- корневой стек `RootStack`;
- нижняя навигация `RootTabs`;
- стек ленты;
- стек поиска;
- стек создания публикации;
- стек профиля;
- отдельный административный стек.

Основные вкладки:

| Вкладка | Назначение |
| --- | --- |
| `FeedTab` | Лента публикаций, публикации, профили, сообщества, уведомления. |
| `SearchTab` | Поиск пользователей и сообществ. |
| `AddPostTab` | Создание публикации. |
| `ProfileTab` | Профиль пользователя и связанные экраны. |

Административный стек доступен только пользователям, для которых проверка `isUserAdmin(me)` возвращает положительный результат.

## Deep links

Файл `src/navigation/linking.ts` описывает web-маршруты для экранов:

- `/feed`;
- `/search`;
- `/create`;
- `/profile`;
- `/feed/post/:id`;
- `/feed/community/:id`;
- `/admin/reports`;
- `/admin/deleted-posts`;
- `/admin/community-verification-requests`.

Это позволяет открывать отдельные экраны по URL в web-версии приложения.

## Работа с API

Клиентский tRPC-клиент настроен в `src/lib/trpc.tsx`.

Для запросов используются:

- `@trpc/client`;
- `@trpc/react-query`;
- `@tanstack/react-query`;
- общий тип API из пакета `shared`.

При выполнении запроса клиент получает JWT-токен из `tokenStorage` и добавляет его в заголовок:

```text
Authorization: Bearer <token>
```

React Query отвечает за кэширование результатов запросов на клиенте, состояние загрузки и обновление данных после мутаций.

Типовой поток данных выглядит так:

1. Экран вызывает tRPC query или mutation.
2. tRPC-клиент добавляет JWT-токен, если пользователь авторизован.
3. Сервер выполняет процедуру и возвращает типизированный результат.
4. React Query обновляет состояние запроса.
5. Экран перерисовывает интерфейс на основе новых данных.

## Формы

Формы вынесены в `src/components/forms`. Среди них:

- регистрация;
- вход;
- создание публикации;
- редактирование публикации;
- создание комментария;
- создание сообщества;
- редактирование сообщества;
- изменение профиля;
- изменение пароля;
- загрузка аватара;
- загрузка изображений публикации.

Валидация форм опирается на схемы данных, совместимые с серверными Zod-схемами.

## Загрузка изображений

Клиент использует Expo Image Picker для выбора изображений. Перед отправкой изображения клиент запрашивает параметры загрузки через процедуру `prepareCloudinaryUpload`, после чего загружает файл во внешний сервис Cloudinary.

Изображения используются для:

- аватаров пользователей;
- аватаров сообществ;
- изображений публикаций.

## Ошибки и обратная связь

Ожидаемые бизнес-ошибки помечаются сервером как `isExpected`. Клиентский tRPC link использует этот признак, чтобы не отправлять ожидаемые ошибки в Sentry.

Неожиданные ошибки:

- выводятся в консоль в непроизводственном режиме;
- отправляются в Sentry;
- могут быть показаны пользователю через слой `AppFeedbackProvider`.

## Аналитика

При изменении активного экрана `NavigationContainer` вызывает отправку события просмотра экрана в Mixpanel. Это позволяет анализировать навигацию пользователя по приложению.
