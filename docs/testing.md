# Тестирование

## Назначение документа

Документ описывает текущий подход к тестированию проекта `Универ`, доступные команды и зоны, которые требуют дополнительного покрытия.

## Инструменты

В проекте используется Jest с TypeScript через `ts-jest`.

Конфигурации:

| Файл                    | Назначение                            |
| ----------------------- | ------------------------------------- |
| `jest.config.js`        | Общая конфигурация Jest.              |
| `server/jest.config.js` | Конфигурация тестов серверной части.  |
| `webapp/jest.config.js` | Конфигурация тестов клиентской части. |
| `shared/jest.config.js` | Конфигурация тестов общего пакета.    |

## Команды

Запуск тестов сервера:

```bash
pnpm --filter @somnia/server test
```

Запуск тестов webapp:

```bash
pnpm --filter @somnia/webapp test
```

Запуск тестов shared:

```bash
pnpm --filter @somnia/shared test
```

Проверка типов:

```bash
pnpm types
```

Проверка lint:

```bash
pnpm lint
```

## Unit-тесты

Unit-тесты покрывают отдельные вспомогательные функции без запуска полного приложения.

Текущее покрытие включает:

- проверки прав доступа в `server/src/utils/can.unit.test.ts`;
- рекурсивное преобразование данных в `server/src/utils/deepMap.unit.test.ts`.

Эти тесты проверяют небольшие изолированные функции и помогают предотвратить регрессии в общей серверной логике.

## Интеграционные тесты

Интеграционные тесты используют реальный tRPC caller и тестовую базу данных.

Общие утилиты находятся в `server/src/test/integration.ts`. Перед каждым тестом очищаются таблицы, участвующие в проверяемых сценариях.

Текущее покрытие включает:

- `setPostLike.integration.test.ts` - создание и снятие лайка, уведомления о лайках, отсутствие уведомления при лайке собственной публикации;
- `setUserFollow.integration.test.ts` - уведомления при подписке и защита от дублирования уведомлений.

## Требования к test-окружению

Интеграционные тесты должны запускаться с:

```text
NODE_ENV=test
```

Серверная конфигурация проверяет, что имя тестовой базы данных заканчивается на `-test`. Это снижает риск случайной очистки development или production базы.

Для применения миграций тестовой базы используется:

```bash
pnpm --filter @somnia/server pmt
```

## Ручное тестирование

Часть пользовательских сценариев требует ручной проверки через интерфейс:

- регистрация и вход;
- создание и редактирование публикации;
- загрузка изображений;
- создание комментариев и ответов;
- создание и редактирование сообщества;
- назначение модераторов;
- черный список сообщества;
- создание жалобы;
- обработка жалобы в админ-панели;
- обработка заявки на верификацию;
- переходы по deep links;
- web-сборка и отображение в браузере.

## Критерии приемки перед выпуском

Перед выпуском версии рекомендуется выполнить:

```bash
pnpm types
pnpm lint
pnpm --filter @somnia/server test
pnpm --filter @somnia/webapp build:web
pnpm build:server
```

Эти проверки подтверждают типовую корректность, базовое качество кода, прохождение серверных тестов и успешную сборку клиентской и серверной частей.
