# Модель данных

## Общая характеристика

База данных проекта `Универ` построена на PostgreSQL. Доступ к данным реализован через Prisma ORM. Основная схема находится в `server/src/prisma/schema.prisma`.

Модель данных отражает предметную область социальной платформы: пользователи, публикации, комментарии, сообщества, роли, подписки, уведомления, жалобы и административные действия.

## Основные сущности

| Сущность                       | Назначение                                                                        |
| ------------------------------ | --------------------------------------------------------------------------------- |
| `User`                         | Учетная запись пользователя, профиль, права, связи с публикациями и сообществами. |
| `Post`                         | Публикация пользователя или сообщества.                                           |
| `Comment`                      | Комментарий к публикации, включая ответы на комментарии.                          |
| `PostLike`                     | Связь пользователя и понравившейся публикации.                                    |
| `Community`                    | Тематическое сообщество с владельцем, участниками и публикациями.                 |
| `CommunityMember`              | Участник сообщества и его роль.                                                   |
| `CommunitySubscription`        | Подписка пользователя на сообщество.                                              |
| `CommunityBlacklist`           | Черный список сообщества.                                                         |
| `CommunityActionLog`           | Журнал действий в сообществе.                                                     |
| `UserFollow`                   | Подписка одного пользователя на другого.                                          |
| `UserBlockedUser`              | Блокировка пользователя пользователем.                                            |
| `UserBlockedCommunity`         | Блокировка сообщества пользователем.                                              |
| `Report`                       | Жалоба на публикацию или пользователя.                                            |
| `CommunityVerificationRequest` | Заявка на верификацию сообщества.                                                 |
| `Notification`                 | Уведомление пользователя о событии.                                               |

## Пользователи

`User` является центральной сущностью системы. Пользователь имеет уникальные `nickname` и `email`, пароль, имя, аватар и набор связей с другими сущностями.

Связанные возможности:

- публикации;
- комментарии;
- лайки;
- подписки;
- владение сообществами;
- участие в сообществах;
- блокировки;
- жалобы;
- уведомления;
- административные права.

Права пользователя представлены enum `UserPermission`: `DELETE_POST`, `ALL`, `SUPER_ADMIN`.

## Публикации

`Post` хранит заголовок, описание, текст, изображения, дату создания, автора и сведения об издателе.

Поле `publisherType` определяет, опубликована запись пользователем или сообществом. При публикации от имени сообщества используется связь `publisherCommunity`.

Для публикаций предусмотрено мягкое удаление через `deletedAt`.

## Комментарии

`Comment` связан с публикацией и автором. Для ответов используется рекурсивная связь `parent` и `replies`, что позволяет строить дерево комментариев.

Удаление комментария также реализуется через `deletedAt`.

## Сообщества

`Community` содержит название, описание, аватар, признак верификации, владельца и связи с участниками, подписчиками, публикациями, журналом действий и заявками на верификацию.

Роли участников определяются enum `CommunityMemberRole`:

- `OWNER`;
- `MODERATOR`;
- `MEMBER`.

## Модерация сообществ

Модерационная модель включает:

- `CommunityMember` для ролей участников;
- `CommunityBlacklist` для блокировки пользователей в рамках сообщества;
- `CommunityActionLog` для фиксации действий владельца или модератора.

Типы действий хранятся в enum `CommunityActionType`, включая назначение модератора, снятие модератора, передачу владения, публикацию, обновление и удаление записей.

## Жалобы и администрирование

`Report` описывает жалобу на публикацию или пользователя. Цель жалобы определяется enum `ReportTargetType`, а состояние обработки - enum `ReportStatus`.

Заявки на верификацию сообществ хранятся в `CommunityVerificationRequest` и проходят статусы из enum `CommunityVerificationRequestStatus`.

## Уведомления

`Notification` связывает получателя, инициатора события и дополнительные объекты: публикацию, комментарий или сообщество.

Типы уведомлений представлены enum `NotificationType`. Среди них лайк публикации, комментарий, ответ на комментарий, подписка пользователя, блокировка в сообществе, новые административные события.

## Индексы и ограничения

В схеме используются уникальные ограничения и индексы для часто используемых запросов:

- уникальные `email` и `nickname` пользователя;
- уникальная пара пользователь-публикация для лайков;
- уникальная пара подписчик-пользователь для подписок;
- уникальная пара пользователь-сообщество для членства и подписки;
- индексы по датам создания, статусам, идентификаторам пользователей и сообществ.

Эти ограничения поддерживают целостность данных и ускоряют выборки ленты, профилей, подписок, жалоб и уведомлений.
